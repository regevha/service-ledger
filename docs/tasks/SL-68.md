# SL-68 hand-off: More menu hardening

**Built (issues #324, #325):**
- Tab and Shift+Tab inside the menu close it and put focus on More first, so the browser moves on from More and never from a menu item that is about to disappear.
- A resize that unfolds every tab while the menu is open used to drop focus to the page body. Focus now goes to the tab that took the focused item's place (More itself is hidden once nothing is folded, so it cannot hold focus; this differs from the PLAN wording "focus on More").
- `aria-controls` points at the menu id (a `useId`, present while the menu is open); when the current view is folded into More, More is announced as "More, current view: <name>".
- The width measure runs in `flushSync` and also observes the tab buttons.
- `12-topbar-more.css` uses logical properties (`inset-inline-*`, `text-align: start`).
- `topbar-more-menu.spec.ts`: arrow-key wrap, Tab and Shift+Tab out of the menu, a folded tab unreachable with Tab, resize while open, aria-controls and the folded-view label.

**Not done (outside `files_touched`):** the misleading comment at `topbarOverflow.test.ts:12`.

**Checks:** `tsc -b` clean, Vitest 61 passed. The Playwright spec runs in CI (no backend dependencies in the lead's sandbox).
