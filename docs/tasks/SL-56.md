# SL-56 hand-off: top bar tabs fold into More

**Built:** `components/TopbarTabs.tsx` holds the top bar's tab list and its icons (moved out of `App.tsx`). On desktop and tablet widths (above 620 px) tabs that do not fit leave from the right, one at a time, into a **More ▾** menu, and come back as space returns. A phone keeps its bottom bar and its own More tab.

**Overflow rule:** `shownTabs()` in `topbarOverflow.ts` (pure, Vitest-tested). When every tab fits, all show and More is not counted. Otherwise tabs fold from the right, leaving room for More, **but the current view's tab never folds**: it keeps its place and the tab before it folds instead, even when the active tab alone does not fit beside More (user decision on #322). Measuring uses a ResizeObserver on the row and the page, runs again when the web font loads and when the current view changes. Folded tabs stay in the page, invisible and out of the tab order, so they can still be measured; they keep their `data-testid`.

**Admin:** keeps `margin-left: auto` (from `01-shell-forms-intake.css`), so on wide screens it sits at the right end of the row as before (#322). It is the last tab, so it is the first to fold when space runs out and it is not the current view.

**Menu:** `role=menu` and `menuitem`, `aria-haspopup`, `aria-expanded`; Arrow keys, Home and End; Escape returns focus to More; an outside click or Tab closes it; after a choice focus returns to More. Since the current tab never folds, More is never marked active for a tab view and no menu item carries `aria-current` in practice; the code for both is kept for safety.

**No component test:** Vitest runs in node here (no DOM), so `TopbarTabs.test.tsx` was dropped from `files_touched` (commit 805a037). The lead accepts this: the rule is a pure function with unit tests, and the component is covered by `topbar-more-menu.spec.ts` (fold and return at 900 and 1400 px, Admin at the right end, the active tab never folding, the keyboard path, the phone layout).

**Existing specs:** at Playwright's default 1280 px all seven tabs fit, so specs that click `tab-admin` or `tab-templates` are unaffected; the full e2e run on this PR confirms it (#323).

**Browser check (lead, 2026-11-13):** Chromium at 1280, 1100, 900 (on Admin), 700 (on Templates) and 640 px (1280 at 200% zoom, on Reports, menu open). Admin at the right end when all fit; the current tab stays in the bar at every width; no wrapping or sideways scroll.
