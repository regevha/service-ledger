# SL-69 hand-off: re-read finalized reports for an accuracy baseline

**Built:** `backend/scripts/reread_baseline.py`, a script for the developer's own machine (not part of the app or the worker). It finds finalized reports with no first reading (`original_fields` is null), re-reads the stored document of each with the current extraction (`extraction.extract`, the same call the worker makes) and compares the result with the approved values. Same "kept as read" rule (`home_summary._same`, empty readings not counted) and same confidence bands as the accuracy page (`read_accuracy._band`).

**Use (from `backend/`):**
```
python -m scripts.reread_baseline                    # counts only; no Claude call
USE_LIVE_CLAUDE=true ANTHROPIC_API_KEY=... python -m scripts.reread_baseline --run --limit 20
```
The key goes in the shell environment only. `--limit` defaults to 20 and is capped at 60 (one Claude call per report in a live run). Newest finalized reports first. The attachment read is the one of the report's latest succeeded extract job, else its first attachment.

**Output:** counts and field names only: reports re-read and skipped, fields read, share equal to the approved value (total, per confidence band, per field worst first). No value, report name, technician, file name or path; the exception text of a failed read is not printed (a test checks this). Nothing is written to the database.

**An estimate:** a second read can differ from the first without either being wrong, and the worker's serial-number correction (`correct_serial_typos`) is not applied here, so the serial field can read a little worse than in the app.
