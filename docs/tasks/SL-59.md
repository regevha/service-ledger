# SL-59: several PDFs on the New report screen

Built
- Choosing or dropping two or more files that are **all PDFs** on New report opens the batch screen with those files, as a drop on Home does. Nothing is read until the person starts it.
- One PDF, or one or more photos, keeps the single-report flow.
- Mixes are refused and the screen stays on New report (user decision on #326):
  - one PDF with photos: "Drop one PDF, or photos of the pages — not both. To upload several reports, choose only PDFs."
  - two or more PDFs with photos: "Upload the PDFs and the photos separately: each PDF becomes its own report, and photos of the pages make one report." (`PDFS_WITH_PHOTOS`)
  - two or more PDFs with a file that is not a PDF or an image: the usual "… is not a PDF or an image" message naming that file.
- Screen text: the drop zone shows "Several PDFs? Each becomes its own report." The link under the heading now reads "Have a pile of PDFs? Drop them all here, or open the several-files screen." (data-testid="open-batch" kept). The hint line under it (`IntakeScreen.tsx`, `hint-text`) gained "(several PDFs: each becomes its own report)". The main drop-zone line is unchanged (an existing spec checks it).

Interface
- `chooseIntakeRoute(files)` in `frontend/src/uploadFiles.ts` returns `{ kind: 'single' }`, `{ kind: 'batch' }` or `{ kind: 'problem', message }`. `isPdfFile(file)` is a helper that returns a boolean. `dropProblem` is unchanged apart from the mix message.
- `IntakeFlow` and `IntakeScreen` take `onBatchFiles(files)`. When it is set, both the drop and the file picker use `chooseIntakeRoute`; without it they fall back to `dropProblem`. `App.tsx` has one `openBatchWith(files)` used by Home and New report.
- The 30-file limit and file-type notes stay in BatchIntake.
