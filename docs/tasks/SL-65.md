# SL-65 hand-off: measuring how much of the reading people keep

**Built:** Admin > Reading accuracy and `GET /analytics/read-accuracy?days=` (rebuilt on `main` from PR #305, without its glossary and learning parts, which are SL-66 and SL-67). A field counts when the first reading (`reports.original_fields`) filled it; it is kept when the approved value equals it. Goal 99%. Home's tile links to the page and uses the same rules (test: Home and page agree for the same 30 days).

**New against #305:**
- `filled_by_hand`: fields the reading left empty that a person filled in. Not part of the percentage.
- `by_confidence`: share kept per band (below 0.70, 0.70 to 0.85, 0.85 and up), from `field_confidences` of the report's latest succeeded extract job. Tells whether the confidence points people at the right fields.
- `by_prompt`: each extract job records `prompt_hash` and `model` in its existing `params` JSON (no migration). `services/extraction.py` (`hash_prompt`) computes it the same way as `scripts/prompt_eval.py` (a test checks they agree; `prompt_eval.py` itself is not in SL-65's files, so it was left alone). The stored hash covers the text prompt without the optional box-location block. Jobs from before this show as "Before this was recorded".
- `VITE_API_BASE_URL= npm run dev` sends API calls through the Vite dev server (README, "Running through one port"). Off unless the variable is set to the empty string.

**Local run (stub mode):**
```
# backend/ (venv active, Postgres up)
python -m app.seed_accuracy_demo     # about 80 invented finalized reports with first readings, jobs, confidences, two prompt hashes
uvicorn app.main:app --port 8000
# frontend/
VITE_API_BASE_URL= npm run dev       # then open http://localhost:5173/#/admin/accuracy
```
A report shows up in the figures only if it was finalized after its reading was stored. Reports seeded by `seed_demo_reports.py` or `seed_trend_demo.py`, or finalized before `original_fields` existed, are not counted.
