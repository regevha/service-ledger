## For backend-dev

- Use the model and enum names above. The plan's `AllowEntry` (SL-68) is `IntakeAllowEntry`.
- The database refuses (IntegrityError) the following, so the services must not try:
  - an allow entry whose `value` is not lower-case, an `address` with no `@`, or a `domain` with an `@`;
  - a sender address or label on a message whose outcome is `unknown_sender` or `sender_not_verified`;
  - a `sender_address` without a `sender_label`, or the other way round;
  - `reply_status` other than `none` on a message without a stored address;
  - `reply_sent_at` unless `reply_status = 'sent'`;
  - `held_path` on a file whose outcome is not `held` (release and delete clear it in the same update);
  - `waiting_kind` unless `read_state = 'waiting_for_limit'` (clear it when the job is queued);
  - `message_key` or `content_sha256` that is not 64 lower-case hex characters (`hashlib.sha256(...).hexdigest()` is);
  - a `report_sources` row with `channel = 'email'` and no address or label.
- A duplicate `message_key` raises IntegrityError on `uq_intake_messages_message_key` (AC-18). Check first, and treat a
  race on that constraint as "already handled".
- `ReportSource.intake_file` is lazy `select`. Where `ReportOut.source.read_state` is built for many reports, load it with
  `selectinload(Report.source).selectinload(ReportSource.intake_file)`.
- Deleting a report through the ORM deletes its `report_sources` row. The database sets `intake_files.report_id` to NULL.
  Deleting an `intake_messages` row (pruning) deletes its files and sets `report_sources.intake_file_id` to NULL.
- Pruning must skip messages that still have a `held` file (DATA_MODEL.md, "Retention"). There is no constraint for this.

## For the tester (SL-62)

- Nothing is seeded, so tests need no separate seeding path.
- `tests/conftest.py` does not truncate `intake_messages` or `intake_allow_entries`. `TRUNCATE reports CASCADE` empties
  `report_sources` and `intake_files` only. Until conftest lists the two tables, a test that adds rows to them must
  clean up after itself. conftest is in no task's `files_touched`, so this needs a spec change from the lead.
- A migration test should create its own throwaway database, as `tests/test_index_migration.py` does.
  `downgrade 0016_relative_attachment_paths` must leave no `intake_*` or `report_source_channel` type and keep
  `extraction_job_kind`.
- Checked by hand on a `create_all` database: every CHECK and UNIQUE above rejects a bad row; the report delete and
  message delete cascades work; `drop_all` leaves no enum type behind.
