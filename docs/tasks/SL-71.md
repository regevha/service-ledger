# SL-71 hand-off: the accuracy page shows what changed in a correction

**Why:** on the first real baseline (9 re-read reports) the corrections list cut long texts at 160 characters, so for a long work description the read and approved columns looked the same. The prompt table showed four hashes for nine reports (each form's field list has its own hash). The intro said "exactly".

**Built:**
- Each correction carries `changes` (the changed phrases as before and after pairs, the same phrase comparison the translation fixes use, at most 8; text values only), and `read_full` / `kept_full` (up to 4000 characters). The page shows the changed phrases in place of the two cut-off texts, with "Show the full text" one click away. Numbers and lists keep the old read / approved cells.
- `by_prompt` rows carry `form` and are listed form by form (then by reports); the table reads "Form, prompt, model".
- The intro says a field counts when approved without a change to what was read, and that written descriptions ignore case, spacing and punctuation.
- No change to what is measured, no migration, same data the page already showed.

**Checks (2026-11-14):** backend 1386 passed, 11 xfailed, coverage 95.58%; ruff clean; mypy 75 (baseline 75); `tsc -b` clean; Vitest 61 passed. Playwright runs in CI (`read-accuracy.spec.ts` checks the new intro). The look at the running page at 1280 and 390 px is still to do on the real data after merge.
