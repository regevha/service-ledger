# SL-57 hand-off: light-mode control borders at 3:1

**Built:** light `--input-border` in `frontend/src/index.css` changed from `#b4bdd0` (1.9:1 on white) to `#7d889f`. Every rule that uses the variable is a control: inputs, textarea, select, `.btn`, the theme toggle, the status filter pills and the Ask button. Dark values are unchanged.

**Contrast (WCAG formula):** 3.56:1 on `--surface` and `--paper`, 3.29:1 on `--bg`, 3.15:1 on `--surface-2`. A light button on hover sits on `--surface-2`, so its hover border is only 3.15:1: it passes, with little margin. Any future darkening of `--surface-2` or lightening of the border needs a recheck.

**Guard:** `accessibility.spec.ts` has "light-mode control borders reach 3:1 against the surface". It measures a plain `.btn` (added to the page for the check) and the intake name field against `--surface`, so a later token edit cannot quietly undo this.

**Design system:** `docs/design-system/tokens.json` (SL-58) copies the colour tokens; it is updated to `#7d889f` in SL-58, which merges after this task.

**Not done here:** dark `#7280a0` is 2.70:1 on dark `--surface-2` (button hover). Tracked as #314 (deferred).

**Browser check (lead, 2026-11-13):** intake and Reports at 1280 px in light and dark, in Chromium. Light field and button borders read clearly as controls; dark looks as before.
